サイトのデザインを変えるには

2026-10-26 ／ 使い方

このサイトの「テーマ」を切り替えると、同じ記事が違うデザインで表示されます。 変わるのは色だけではありません。記事一覧、記事詳細、サイト紹介を、それぞれのデザインに合わせたテンプレートで表示しています。 従来の見た目は「ナチュラル」として残しています。

自分のサイトでは、一つ選んで固定できます

ソースをダウンロードした人がそのまま使いやすいように、設定ファイルの初期値では切り替えをOFFにしています。 この公開デモだけ、ビルド時にONへ上書きしています。

content/sites/sample.yml の次の設定で、使うデザインを選びます。

theme_switcher: false
template: notion

これは「切り替えUIを出さず、Notion風で全ページを表示する」という設定です。 template: natural なら元のデザインです。ほかに apple、dala、dope を選べます。 現在の組み込みテンプレートはサイトID sample 用です。サイト名や文章は自由に変えられます。

設定を変更したら再ビルドします。GitHubへpushして公開する場合は、自分のリポジトリのActionsがビルドします。 ON/OFFを切り替えるスイッチを画面に出す方式ではなく、設定ファイルで決める方式です。 OFFの場合はブラウザに残っている過去の選択も使わず、指定したデザインに固定します。

DESIGN.mdから、自分のデザインを作る

DESIGN.mdは、配色、書体、余白、レイアウト、部品の見た目などをまとめたデザインの仕様書です。 使いたいDESIGN.mdをAIコーディングツールに渡すと、その内容に合わせたテンプレート作りを依頼できます。

渡し方は、インターネット上のURL、本文のコピー、手元に保存したファイルのどれでも構いません。 AIがURLを読めない場合は、本文を貼るかファイルを渡します。 このサンプルでは、Refero Styles の各スタイルページのURLをAIに渡し、ページに掲載された資料を読んでテンプレートを作りました。 DESIGN.mdファイルそのものを用意しなくても、デザイン資料が掲載されたページのURLから相談できます。

例えば、ソースを開いたAIコーディングツールに、次のように依頼します。

このMarkdown CMSに、次のスタイルページまたはDESIGN.mdを元にしたテンプレートを追加してください。
デザイン資料：［URL、ファイルパス、または本文を貼り付け］
サイトの用途：［自分のサイトの用途と読者］

色だけでなく、ページ構成、見出し、余白、ナビゲーション、
カード、写真の扱いまでデザイン資料に合わせてください。
記事一覧・記事詳細・サイト紹介を一式作ってください。
いまのナチュラルと既存テンプレートは残してください。

新しいテンプレートを設定から選べるようにし、固定表示で使います。
theme_switcherはfalseにしてください。
記事データ、URL、検索、カテゴリ、言語切り替えを維持してください。
ソースを編集して再ビルドし、テストとPC・スマートフォン幅の表示確認をしてください。
guides/DESIGN_CUSTOMIZATION.md と guides/TOOLS.md も読んで進めてください。

文章や表で書かれたDESIGN.mdでも、AIが読んでページを実装できます。 一度テンプレートを作れば、公開後のサイトの表示や切り替えにAIは必要ありません。

どんなツールが必要？

記事や設定を編集するエディタ、見た目を確認するブラウザ、サイトを生成するPythonが基本です。 DESIGN.mdからの制作をAIに依頼する場合は、プロジェクトのファイルを読んで編集できるAIコーディングツールを使います。 Node.jsは表示処理のテストに、GitとGitHubは変更の管理と公開に使います。

必要なソフトの説明とWindows・macOS・Linuxでの準備手順は、ツールと動作確認 にまとめています。

作ったら、確認して公開する

python scripts/build.py
python -m unittest discover -s scripts -p 'test_*.py'
node scripts/test_frontend.cjs
python scripts/export_preview.py

Pythonの依存パッケージをインストールした環境で実行し、dist/preview.html を開いて確認します。 通常の公開形式もローカルサーバーで確認できます。具体的な手順はツールの資料を参照してください。 テストにはサンプル名やサンプル記事が前提のものもあるため、自分のサイトに変えた場合はテストも調整します。

色の読みやすさ、スマートフォンでの表示、記事の画像、検索なども見てください。 確認できたら、自分のGitHubリポジトリにpushします。
