# デザインを変えるためのガイド

このOSSをコピーした後に、自分のサイトのデザインを変える手順と、AIへ渡す指示例です。
必要なソフトと起動コマンドは [ツールと動作確認](TOOLS.md) にまとめています。

## まず決めること

| やりたいこと | 進め方 |
|---|---|
| サイト名・文章・アクセント色・写真を変える | `content/sites/sample.yml` と記事・画像を編集 |
| 既存テンプレートを一つ選んで使う | 設定ファイルの `template` を変更 |
| DESIGN.md の雰囲気でサイト全体を作る | 資料をAIに渡し、一覧・詳細・紹介のテンプレート実装を依頼 |
| 既存デザインを残し、新しいデザインも選べるようにする | テンプレートを追加し、設定で切り替えを有効化 |
| 対応するYAMLの色・書体などだけ反映する | `scripts/design.py` でトークンを取り込み |

DESIGN.md は「どんな見た目にするか」の仕様書です。文章や表で書かれていても、AIが読んでHTML・CSSを実装できます。
一度テンプレートになれば、公開サイトの表示にAIやAI APIキーは必要ありません。

## 既存テンプレートを固定で使う

`content/sites/sample.yml` を編集します。

```yaml
theme_switcher: false
template: notion
```

| `template` | デザイン |
|---|---|
| `natural` | 従来のナチュラル。配布ソースの既定値 |
| `apple` | 写真と余白を使うギャラリー |
| `notion` | 紙色の背景とサイドバーを使うノート |
| `dala` | 黒い背景、大きな文字、左右に配置した記事 |
| `dope` | 斜体の見出し、等幅ラベル、搭乗券風の案内 |

ビルド後、一覧・記事詳細・サイト紹介に同じテンプレートが適用されます。
切り替えをOFFにすると、以前ブラウザに保存されたテーマ選択も使わず、設定のデザインに固定します。
現在、これらの組み込みテンプレートはサイトID `sample` 用です。サイト名・本文は自由に変更できます。
サイトIDも変える場合は、下の指示例のようにルーティング・テンプレート・テストを一緒に調整します。

配布ソースの `theme_switcher` は `false` です。
[公開デモ](https://oosawak.github.io/markdown-cms-oss/) は、GitHub Actions が元リポジトリを判定し、
ビルド時だけ環境変数 `THEME_SWITCHER=true` を渡して切り替えをONにしています。
forkやテンプレートから作った別リポジトリではこの上書きは行われず、YAML設定が使われます。
ダウンロード済みの `docs/`・`preview.html` は公開デモ用の生成物なので、自分の設定で再ビルドしてください。

自分のサイトでも比較用に切り替えを出したい場合は、設定を `theme_switcher: true` にします。
この場合の `template` は初回表示のデザインで、次回以降はブラウザに保存した選択を使います。

## DESIGN.md の渡し方

| 渡し方 | AIへの伝え方 |
|---|---|
| インターネット上のURL | DESIGN.mdそのもの、またはデザイン資料を掲載したページのURLを渡す |
| テキストをコピー | 「以下がDESIGN.mdです」と本文を貼る |
| 手元のファイル | `content/design/my-design.md` などへ保存してパスを渡す |

URL先を読めないAIツールの場合は、本文をコピーするかファイルを保存します。
このサンプルの制作では、[Refero Styles](https://styles.refero.design/) の各スタイルページのURLをAIへ渡しました。
AIがページ上のDESIGN.md形式の資料や配色・書体などの説明を参照して実装しています。
DESIGN.mdを自分でダウンロードしたり、本文を貼り付けたりすることは必須ではありません。
残したい元のデザインと、新しく作るデザインの名前も伝えてください。

## そのまま渡せる指示例

`［ ］` を自分の内容に置き換えて使います。

### A. サイト全体を新しいデザインにする

```text
このリポジトリの Markdown CMS を、自分のサイト用に変更してください。
README.md と guides/DESIGN_CUSTOMIZATION.md を読んでから作業してください。

サイト名：［サイト名］
用途・読者：［パン屋のお知らせ／地域のニュース／個人ブログなど］
デザイン資料：［スタイルページやDESIGN.mdのURL・ファイルパス、または下に本文を貼る］

DESIGN.mdを読んで、色だけでなく、ページ構成、見出しと本文の文字、余白、
ナビゲーション、記事カード、写真の扱いまで反映してください。
記事一覧・記事詳細・サイト紹介の3ページ分を一式のテンプレートとして作ってください。
必要ならHTML構成も変えて構いません。参考サイトの文章・ロゴ・画像は持ち込まないでください。

既存のナチュラルと4つのテンプレートは残し、新しいテンプレートを追加してください。
追加したテンプレートを固定で使い、切り替えUIは設定ファイルでOFFにしてください。
新しいテンプレートIDを設定の検証とビルドのCSS生成にも登録してください。
記事・画像・検索・カテゴリ絞り込み・言語切り替え・既存のURLを維持してください。
サイト名はヘッダー・フッター・ブラウザタブで揃えてください。

生成物を手で直さず、ソースを編集して再ビルドしてください。
既存テストと追加部分の動作確認を行い、通常のページと単一HTMLプレビューで、
PC幅とスマートフォン幅の表示を確認してください。
実施できなかった確認があれば明記し、変更内容とローカルでの確認方法を教えてください。
```

### B. 既存の見た目を残して、比較できるテンプレートを追加する

```text
次のDESIGN.mdを元に、このCMSへ新しいページテンプレートを追加してください。
資料：［URL・ファイルパス、または本文］
テンプレートID：［例：magazine］
表示名：［例：雑誌風］

assets/templates.js に home・detail・about を用意し、レイアウトと部品も資料に合わせてください。
CSSとDESIGN.mdを保存し、assets/app.js の選択肢、scripts/build.py の設定検証・CSS生成、
必要なテストへ登録してください。配色だけの変更ではなく、3ページとも実装してください。
ナチュラルと既存テンプレートはそのまま残してください。

比較用に content/sites/sample.yml の theme_switcher を true にしてください。
表示中の記事を維持して切り替えられ、再読み込み・言語切り替えでも選択が保たれることを確認してください。
公開デモ以外に新たな環境変数の強制上書きを追加しないでください。
ビルド、既存の動作確認、スマートフォン幅での表示確認まで行ってください。
```

### C. いまのデザインを少し直す

```text
いまの［テンプレート名］をベースに、次だけ変更してください。
・［例：本文を少し大きくする］
・［例：カードの余白を増やす］
・［例：アクセントを濃い青にする］

ほかのテンプレートに影響しないようにしてください。
記事データとURLを維持し、一覧・記事詳細・サイト紹介を確認してください。
ソースを編集して再ビルドし、変更ファイルと確認結果を教えてください。
```

### D. サンプルから自分のサイトに仕上げる

```text
このCMSを次の内容で自分のサイトにしてください。
サイト名：［名前］
紹介文：［紹介文］
使うテンプレート：［ID］
サイトID：［sampleのまま／新しいID］
公開先リポジトリ：［自分のowner/repository］

切り替えUIは theme_switcher: false で非表示にしてください。
サンプルのサイト名・アイコン・デモ用文章を自分のサイトに合わせてください。
設定だけで変わらないブランド定義も確認してください。
サイトIDを変える場合は、データパス・ルーティング・テンプレート内のリンク・
ビルド設定・テストを揃えて変更してください。変更後のサイトIDで公開できる状態にしてください。
翻訳元の変更による source_hash の不一致も確認し、必要な翻訳とテストを更新してください。
まずローカルで確認できる状態にし、公開手順を教えてください。
```

## 編集する場所

| ファイル | 役割 |
|---|---|
| `content/sites/sample.yml` | サイト情報、固定テンプレート、切り替えON/OFF |
| `content/design/*.md` | デザイン資料・対応トークン・参照元 |
| `assets/templates.js` | 一覧 `home`・詳細 `detail`・紹介 `about` のHTML構成 |
| `assets/style.css` | レイアウト、配色、書体、レスポンシブ対応 |
| `assets/app.js` | ルーティング、ブランド、テンプレート選択肢、表示処理 |
| `assets/favicon.svg` | サンプルのタブ用アイコン。ヘッダーのアイコンは `app.js` 内 |
| `scripts/build.py` | 設定の検証、CSS生成、JavaScript結合、公開HTML生成 |
| `content/i18n/en.json` | 英語のサイト情報と翻訳元のハッシュ |
| `scripts/test_frontend.cjs` | サンプルのページ遷移・テンプレート・切り替えOFFの動作確認 |
| `.github/workflows/build.yml` | 自動ビルドと、元リポジトリのデモ限定設定 |

`data/`・`docs/`・`preview.html` は生成物です。手で修正しても次のビルドで置き換わります。
特に `docs/assets/app.js` は `assets/templates.js` と `assets/app.js` を結合したものです。
ヘッダー・フッターなど共通部分を変える際も、ほかのテンプレートへの影響を確認します。

## YAMLの値だけ取り込みたい場合

`scripts/design.py` は、対応するYAMLの色・書体・角丸などを読み込む補助ツールです。
文章や表からページ全体を作るときは、上のAI向け指示例を使います。

```bash
python scripts/design.py --file /path/to/DESIGN.md
# URLなら --url https://example.com/DESIGN.md
# 貼り付けなら --stdin（macOS/Linuxは最後に改行してCtrl-D）
```

Windowsでの貼り付けは、エディタでファイル保存して `--file` を使うと確実です。
取り込み結果は `content/design/custom.md` に保存されます。
サイト設定へ `design: design/custom.md` を追加すると対応トークンが反映されます。
固定テンプレートの配色と重なる場合があるので、実際のプレビューで確認してください。
対応一覧・Raw URLの例は [README](../README.md#designmd-のトークンを取り込む) にあります。

## 確認と公開

[ツールと動作確認](TOOLS.md) の手順で再ビルドし、`dist/preview.html` を開きます。
一覧・詳細・紹介、検索、カテゴリ、言語切り替え、画像、スマートフォン幅を確認します。
切り替えをOFFにした場合は、以前の選択がブラウザに保存されていても固定表示になることも確認します。

自分のGitHubリポジトリにpushすると、Actionsが生成物を更新します。
Pagesは `main` の `/docs` を公開元に設定してください。
ZIPでダウンロードした場合は、自分のリポジトリを作り、ソースを登録してから公開します。
変更履歴を戻せるようにしておけば、新しいデザインが合わなかった場合も戻せます。
